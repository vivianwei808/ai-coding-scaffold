编写任何智能体消费的文档的参考：技能、`AGENTS.md` / `CLAUDE.md`、通过指针触达的文档。包装方式不同；写作方式不变：同样的杠杆让每份文档变得可预测，因为智能体每次运行采用相同的*过程*，而不是产生相同的输出。

当你要写的文档是技能时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解前置元数据、调用方式选择以及路由技能。

## 上下文指针（Context Pointers）

**上下文指针**是保存在智能体上下文中的一个引用，它命名了当前不在上下文中的材料并编码了触达它的条件。技能描述就是一个；`AGENTS.md` 中命名某个文档的一行也是同一个东西。指针的*措辞*——而不是它指向的目标——决定了智能体何时触达这份材料，以及触达的可靠性。目标必要但指针措辞弱，就是一个方差 bug：先打磨措辞，只有在打磨无效时才内联材料。

指针做两件事：说明材料是什么，并列出应该触发触达的**分支**（分支是文档处理的独立场景，不同的运行会走不同的路径）。常驻指针的每个词每轮都在消耗 token，所以它需要比正文更严格的修剪：

- **把关键词前置**：指针就是靠它来触发工作的。
- **每个分支一个触发器。** 重命名单个分支的同义词是重复写一个分支；合并它们，只保留真正独立的分支。
- **删掉正文已经自带的身份信息。**

## 两种负载（The Two Loads）

你添加的每份文档和每个指针都在消耗两种预算之一：

- **上下文负载（Context Load）** 是常驻材料对智能体窗口的消耗：一行 `AGENTS.md`、一个技能描述、每轮都待在上下文中的任何东西——无论是否触发，都在消耗 token 和注意力。
- **认知负载（Cognitive Load）** 是对人的消耗：哪些文档存在、何时去用它们。人是索引。这不是要最小化的成本：它是人类代理权的代价；在需要人类判断的地方投入它，在不需要的地方移除它。

只通过指针触达的材料以指针自身那一行为代价摆脱了上下文负载；没有指针的材料完全靠认知负载承载。

## 信息层级（Information Hierarchy）

文档由两种内容类型构成：**步骤**（智能体执行的有序操作）和**参考**（定义、规则、需要时查阅的事实）。两种可以自由混合：全部是步骤（一份配方），全部是参考（一次审查规则、本技能），或者两者兼有。核心决定是每块内容在**信息层级**上的位置——这是一个按智能体对材料需要的紧迫程度排名的阶梯：

1. **文件内步骤（In-file step）** 是首要层级：智能体要做什么，按顺序排列。
2. **文件内参考（In-file reference）** 按需查阅。通常可以是合法的扁平同级集合（审查的每条规则在同一级），这是一种合理布局，不是异味。
3. **外置参考（Disclosed reference）** 推到单独的文件中，通过上下文指针触达，只在指针触发时加载。范围从同文件夹中的兄弟文件到完全外部的引用——可以放在任何地方，任何文档都可以指向它。

往下推得太少，顶层会臃肿；推得太多，你会隐藏智能体实际需要的材料。这种张力就是全部决策。

**渐进披露（Progressive Disclosure）** 是沿着层级往下移动（离开主文件，藏在指针后面），使顶层保持可读。主要不是 token 优化：它是层级结构的保护方式。分支是最干净的披露测试：内联每个分支都需要的内容，把只有某些分支会触达的内容推到指针后面。当文档有步骤时，应该外置的文件内参考会掩埋它们，把关注它们变成掷硬币：一个方差杠杆，不仅是可读性杠杆。

**合并放置（Co-location）** 是文件内部的配套原则：层级决定一块内容放在*多深的*位置，合并放置决定一旦放在那里*什么放在它旁边*。把概念的 definition、rules 和 caveats 放在同一个标题下，不要分散，这样读一个部分会顺带看到它的邻居。检验标准：文档应该读起来像写给智能体的文档。分组好的材料读起来就是这样；分散的材料不是这样。（与重复不同：重复是在两个地方重复同一个含义；分散是在很多地方碎片化同一个含义。）

**膨胀（Sprawl）** 是这里的失败模式：文档实在太长，即使每一行都是活跃且独特的。注意力在冗余中摊薄，每多一行就多一行需要保持相关性。解药是层级：通过指针外置参考，按分支或顺序拆分，让每条路径只携带它需要的内容。

## 步骤与完成标准（Steps and Completion Criteria）

每一步都以一个**完成标准**结束——告诉智能体工作已完成的那个条件。两个属性使它成为杠杆：

- **清晰度（Clarity）**：智能体能区分完成和未完成吗？模糊的边界（"达成理解"）会诱发**提前完成（Premature Completion）**：在真正完成之前结束步骤，注意力滑向*已经完成了*。仍在眼前的后续步骤（**完成后的步骤**）提供拉力；标准的清晰度是阻力。按优先级防守：**先打磨边界**（局部的、低成本的）；只有当它的模糊性不可约且你*观察到*了这种仓促时，才通过拆分顺序隐藏后续步骤。隐藏只在跨越真正的上下文边界时才有效（交接或子代理派遣；内联调用让后续步骤仍在上下文中，什么都没清除）。
- **要求程度（Demand）**：它要求多少。"每个修改过的模型都已考虑在内"迫使彻底工作，而"生成变更列表"不会。要求驱动**实地工作（Legwork）**——智能体在工作范围内所做的挖掘，潜藏在措辞中而不是写成独立步骤——而且它不仅限于步骤："每条规则都已应用"约束一个参考体，就像"每一步都完成"约束一个顺序一样。这就是一份纯参考文档也能承载穷尽性的标准的方式。

最强的标准既可检查又穷尽一切。

## 何时拆分（When to Split）

把一份文档拆成两份要消耗两种负载中的一种，所以只在拆分值得时才拆：

- **按顺序拆分**：当后续步骤诱惑智能体匆忙完成前面步骤时，拆分一组步骤。让后续步骤不可见会驱使更多实地工作在当前任务上。注意反面：合并顺序让每个步骤的后续步骤暴露给后续内容，诱发提前完成。
- **按调用拆分**，技能特有：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 关键词（Leading Words）

**关键词**是已经存在于模型预训练中的紧凑概念，智能体在运行文档时用它思考（*lesson*、*fog of war*、*tracer bullets*）。作为一个 token——而不是句子——重复使用，它累积出一个分布式的定义，用最少的 token 锚定一整块行为区域，借助模型已经持有的先验。自己造一个词也行，但要定义清楚——人造词不借助任何先验：你用定义 token 支付了预训练词汇免费提供的东西；先找现有的词。

它锚定两次。在正文中，*执行*：每次这个词出现，智能体都会做出同样的行为；在扁平参考中，它把注意力集中到一类要寻找的东西上。在指针中，*调用*：当同一个词出现在你的提示、文档和代码库中时，智能体把这种共享语言链接到材料上，更可靠地触达它。

寻找用关键词重构的机会。三处拼写出来的三件套，一个指针花一句话去描述一个想法。每一处都是乞求坍缩成单个 token 的段落：

- "快、确定性、低开销" → *tight*（一个 *tight* 循环）。
- "一个你信任的循环" → *red*，把模糊的门变成二元可观察状态（循环在 bug 上变 *red*，或者不变）。

你赢两次：更少的 token，以及更锐利的钩子供智能体挂靠思考。假设每份文档都携带着关键词可以退役的重述。去找它们。

**否定（Negation）** 是这个杠杆旁边的失败模式：用禁止来引导会把被禁止的行为拖进上下文，让它*更*容易获得，而不是更少。*别想大象*，大象就是全部；否定是对被强烈激活的概念的一个弱修饰符，它会被覆盖，所以禁令读起来半像指令让你去做这件事。提示**正面**行为：陈述目标行为（"写一行注释"），这样被禁止的行为永远不会被说出。只有当你无法用正面表达时，一个禁止才值得保留；即便如此，也要配上正面目标，让注意力落在该做什么上。

## 修剪（Pruning）

- 把每种含义保持在一个**单一真相来源**：一个权威位置，这样改变行为只需在一处编辑。**重复**（同样的含义在多处出现）消耗维护成本和 token，并把一个含义在层级上的突出度膨胀到超出它的真实等级。（关键词的意外反义词，它故意重复一个 token，从不重复含义。）
- **环境**也是一个真相来源（`package.json` scripts、配置文件、目录布局、`--help` 输出），重复了它们的文档是一个**缓存**：一份查找的副本，只有在查找昂贵时才值得存在。缓存智能体自己找不到的东西：不成文的约定、一个选择背后的原因、没有配置文件坦白的陷阱。把一行文件、一条命令的查找留给环境，在那里它们不会过时。
- 检查每一行的**相关性**：它仍然关系到文档做什么吗？一行失去相关性要么是因为从未关系到任务（纯粹的阐述，或应该外置的分支），要么是因为随着它描述的行为或世界变化而过时。更短的文档更容易保持相关性。没有修剪纪律，默认命运是**沉积（Sediment）**：因为添加感觉安全、删除感觉冒险而堆积的陈旧层，直到你必须穿透它们才能找到仍然活跃的内容。
- 一句一句地猎杀**无操作（No-ops）**：模型已经默认遵守的指示，付出负载却什么都没说。测试标准（它是否改变了相对于默认的行为？）是相对于模型而言的，不是相对于读者而言的：两个人对无关操作的分歧是对默认的分歧，应该通过运行文档来裁决，而不是通过辩论。当一句话判定为无操作时，删除整句话而不是从中裁剪词。这个测试也检验关键词：一个太弱以至于无法胜过默认的词（*be thorough*——当智能体已经差不多 thorough 时）就是无操作，解决方法是更强的词（*relentless*），而不是换一种技巧。
