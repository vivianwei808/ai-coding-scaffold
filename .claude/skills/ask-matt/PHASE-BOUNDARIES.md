# 阶段边界

**阶段**是一个会话中的一块工作：盘问、实现、QA。这个定义有意模糊。当你觉得“好了，这部分完成了”，一个阶段就结束了。

**阶段边界**是两个阶段之间的间隙，也是唯一需要做出上下文决策的地方。阶段中途没有其他选择：继续，或把剩余工作拆给子 agent。阶段中途压缩会让 agent 丢失思路。

## 五个选项

| 选项 | 作用 |
| --- | --- |
| **继续** | 留在当前会话，完全不切换上下文。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 编写一份可移植的 Markdown 文件，用它在任何地方启动新会话。 |
| **Subagent** | 把任务交给独立上下文窗口执行，并拿回报告。 |
| **`/compact`** | 压缩当前上下文，用摘要启动新会话。 |

## 决策树

在阶段边界从上到下判断。第一个**是**就是答案。

**1. 能否在当前会话继续？** 两种情况会让答案为是：下一个阶段需要把当前阶段作为**一手资料**，或者剩余 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k tokens）足以容纳下一个阶段。盘问进入实现是典型的“是”：实现需要逐字保留推理，而不是只拿摘要。继续没有成本，也不损失信息，因此先排除其他选项。

**2. 当前上下文是否与下一步无关？** 这个会话里的探索、决策和走过的弯路是否都可以丢弃？如果是，使用 **`/clear`**。这是成本最低的动作：不花时间，并返还整个上下文窗口。`/clear` 也不是终点，旧会话仍可恢复。

判断错误的代价是单向的。清除一个*相关*上下文会丢失构建结果背后的**原因**，重新阅读 diff 也无法把它找回来。

**3. 是否需要交接？** `/handoff` 的适用范围很窄。只在以下情况使用：

- 切换到**新的 harness**（Claude → Codex）
- 移动到**新目录**或新仓库
- 把工作交给**同事**
- 在**阶段中途**分叉出一个侧任务，又不想打断当前工作

这就是全部适用条件。`/handoff` 提供的是**可移植性**，也就是一份能够移动的文件。如果没有东西需要移动，就不需要它。

**4. 任务能否 AFK 完成？** 任务范围是否足够明确，可以在你离开键盘、无需引导的情况下运行？如果可以，把它交给 **subagent**，保持当前会话不变。自动化审查是典型场景：agent 读取 diff 并报告，执行期间不需要你。

**5. 其他情况使用 `/compact`。** 上下文仍然相关，harness 和目录不变，而且你需要继续参与。决策树经常落到这里。给它附上一条指令（例如 `/compact 接下来要对这个区域做 QA`），让摘要保留下一阶段所需的信息。

`/compact` 是**默认选项，但不是第一选择**。它位于决策树底部，因为上面的四个问题成本更低或更精确。一上来就压缩的失败模式，是新会话对摘要压平的决策产生错误却自信的理解。

## 一手资料与二手资料

除**继续**外，每个动作都会把**一手资料**转化为**二手资料**：真实发生的会话被其摘要替代。权衡始终是同一种形状：

| 来源 | 信息量 | 噪声 | 可用空间 |
| --- | --- | --- | --- |
| 一手资料（继续） | 完整 | 多 | 少 |
| 二手资料（`/compact`、`/handoff`） | 有损 | 少 | 多 |

这就是问题 1 必须排在最前面的原因。只有继续的成本高于收益时，才承受信息损失。

## 这些都需要判断

这些问题没有客观答案，每个问题都含有判断。同一个阶段边界在不同日期可能得到不同选择。价值在于按顺序提问，并且只在阶段边界做出决定，而不是在工作中途。
